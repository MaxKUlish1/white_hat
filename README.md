# white_hat — проверка серверов без вмешательства

Проверка версий ПО и настроек **только чтением**, сверка уязвимостей **у себя** (онлайн OSV.dev или офлайн trivy),
каждое действие — человека и ИИ — в **журнале с цепочкой SHA-256**. ИИ (Claude Code) работает под надзором: сторож
проверяет каждое его действие до выполнения.

## Что делает каждая команда
| команда | что происходит | что НЕ происходит |
|---|---|---|
| `wh project new <имя> "<цель>"` / `use` / `list` | проекты с клятвой «я занимаюсь: … — и ничем другим»; ИИ ведёт их сам, пишет только в текущий | работы без открытого проекта (только чтение) |
| `wh start <IP> [логин]` | добавляет IP в область работ `scope.txt` (не шире /24), объявляет задачу | — |
| `wh plan <IP>` | печатает план работ для администратора: что делаю / чего не делаю / данные / остановка | — |
| `wh outside <IP>` | **без логина**: читает приветствие SSH (порт 22) и по одному запросу http/https; версия пакета из баннера SSH -> сверка уязвимостей офлайн; раскрытые версии веба | сканирования портов, подбора, атак |
| `wh fp <IP>` | отпечаток ключа SSH сервера (`ssh-keyscan`) — сверить с админом до входа | входа на сервер |
| `wh versions <IP> [логин]` | с выданной учёткой: `ssh … 'sh -s' < version.sh` — список пакетов, порты, службы, настройки SSH; сверка у себя | sudo, установки, файлов на сервере |
| `wh sshaudit <IP>` | алгоритмы и настройки SSH (`ssh-audit`, только рукопожатие) | входа, подбора |
| `wh tls <IP> [порт]` | HTTPS: протоколы, шифры, сертификат (`testssl.sh`) | атак |
| `wh web <IP>` | код ответа, заголовок, сервер, технологии (`httpx`, по 1 запросу) | обхода каталогов |
| `wh check [--offline] <файл>` | сверка выгрузки: OSV.dev (онлайн) или trivy (офлайн, ~5 с) + гигиена настроек | — |
| `wh open` | открыть последний отчёт в браузере (HTML: сводка, приоритеты, цвета уровней) | — |
| `wh update-db` | обновить офлайн-базы: CISA KEV, EPSS, trivy, grype, шаблоны nuclei | — |
| `wh cve <CVE-ID>` | описание и оценка уязвимости из локальной базы (офлайн) | — |
| `wh nuclei <IP>` | только после явного «да» с клавиатуры: без dos/fuzz/intrusive, 10 запросов/с | — |
| `wh code <папка>` | разбор кода у себя: semgrep, gitleaks, trivy | — |
| `wh shell` | терминал под надзором: каждая введённая команда — в журнал, сессия — в `logs/` | — |
| `wh report` | итоговый файл + хэш журнала для администратора | — |
| `wh log` / `wh undo` / `wh verify` | журнал / откат последнего изменения / проверка цепочки | — |
| `wh doctor` / `wh demo` / `wh about` | готовность / показ офлайн / схема в браузере | — |

## Приоритеты в отчёте
Каждая найденная уязвимость сверяется с **CISA KEV** (уже используются в реальных атаках) и **EPSS** (вероятность атаки
в ближайшие 30 дней). Отчёт начинается с раздела «СРОЧНО» — что закрыть сегодня, а не просто «795 HIGH». Базы — офлайн.

## Надзор за ИИ (`.claude/settings.json`)
- `guard.py` (до действия, все инструменты): сеть — только через `wh` и только IP из `scope.txt`; запись — только внутри
  папки, файлы надзора и ключи защищены; запрещены sudo, управление службами, установка ПО, сканеры/подбор, eval/сокеты,
  отправка данных наружу. Любая ошибка сторожа = запрет.
- `nadzor.py` (после действия): капсула «ДЕЛАЛ → ПОЛУЧИЛ», автокоммит, откат `wh undo`.
- `jlog.py`: журнал `journal.tsv`, каждая строка содержит хэш предыдущей (с блокировкой файла); `wh verify` ловит правку задним числом.

## Файлы
`version.sh` / `version.ps1` — сбор (Linux / Windows), только чтение · `check.py` — сверка и отчёт · `tools/fetch.py` —
установка инструментов из официальных релизов GitHub со сверкой SHA-256 (osv-scanner, trivy, grype, syft, nuclei, httpx,
subfinder, gitleaks) + semgrep, ssh-audit, testssl.sh · `env.sh` — PATH.
